# 服务器部署指南（Nginx + Node 后台）

本博客是 **Next.js 静态导出（out/）+ 本地 Node 后台（scripts/admin-server.mjs）** 的双进程架构。
在自有服务器上部署 = 网页静态托管 + 后台进程常驻 + API 反向代理。

## 0. 架构总览

```
浏览器 → 域名:443 (Nginx)
           ├── /            → out/ 静态文件（站点页面）
           ├── /admin       → out/admin.html（后台界面，静态页）
           └── /api/*       → 反向代理 → 127.0.0.1:3001（admin-server 后台服务，读写 content/）
```

后台服务必须在**能读写 content/ 目录的机器**上运行，所以整个仓库（含内容）部署在服务器上。

## 1. 服务器准备

```bash
# Ubuntu 22.04 / Debian 12 为例
sudo apt update
sudo apt install -y nginx git
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
node -v   # 应 ≥ 20
```

## 2. 拉取代码并构建

```bash
sudo mkdir -p /srv && sudo chown $USER:$USER /srv
cd /srv
git clone https://github.com/eznine/my-blog.git
cd my-blog
npm ci
npm run build          # 产出 out/
```

把构建目录给 Nginx：

```bash
sudo chown -R www-data:www-data /srv/my-blog/out
sudo chown -R $USER:$USER /srv/my-blog/content /srv/my-blog/public/uploads  # 内容仍归你写
```

## 4. Nginx 配置

```nginx
# /etc/nginx/sites-available/my-blog
server {
    listen 80;
    server_name 你的域名.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name 你的域名.com;

    ssl_certificate     /etc/letsencrypt/live/你的域名.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/你的域名.com/privkey.pem;

    root /srv/my-blog/out;
    index index.html;

    # 站点静态资源（Next 静态导出自带 /_next/、/notes/ 等目录）
    location / {
        try_files $uri $uri.html $uri/ /404.html;
    }

    # 后台静态页
    location = /admin {
        try_files /admin.html =404;
    }

    # API 反代到后台服务（后台页面需同源访问，构建时 NEXT_PUBLIC_ADMIN_API=/api）
    location /api/ {
        proxy_pass http://127.0.0.1:3001;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_buffering off;          # AI 流式输出必需
        proxy_read_timeout 600s;      # AI 长请求
    }

    location /uploads/ {
        alias /srv/my-blog/public/uploads/;
        expires 7d;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/my-blog /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

HTTPS 证书（首次）：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 你的域名.com
```

## 5. 后台服务常驻（systemd）

```bash
sudo tee /etc/systemd/system/my-blog-admin.service > /dev/null <<'EOF'
[Unit]
Description=EZNINE Blog Admin Server
After=network.target

[Service]
Type=simple
WorkingDirectory=/srv/my-blog
ExecStart=/usr/bin/node scripts/admin-server.mjs
Restart=always
RestartSec=3
Environment=NODE_ENV=production
# 如需覆盖配置，可用环境变量
# Environment=ADMIN_PASSWORD=xxx

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now my-blog-admin
sudo systemctl status my-blog-admin
```

访问测试：

- `https://你的域名.com` → 站点

- `https://你的域名.com/admin` → 后台（能登录、能改文章）

## 6. 更新流程

```bash
cd /srv/my-blog
git pull
npm ci
npm run build
sudo chown -R www-data:www-data out
sudo systemctl restart my-blog-admin
```

推送 GitHub 时 GitHub Actions 仍会发布到 GitHub Pages，两者互不影响。
若只想在服务器发布，也可以去掉 Actions 工作流里的 Pages 部署步骤。

## 7. 注意点

- **后台相对路径**：构建时必须注入 `NEXT_PUBLIC_ADMIN_API=/api`（Nginx 已反代 /api），否则后台会去连 127.0.0.1:3001（浏览器里不存在）。

  ```bash
  NEXT_PUBLIC_ADMIN_API=/api npm run build
  ```

  本地开发**不要**设置该变量，保持默认直连 3001。

- **AI 流式输出依赖** Nginx `proxy_buffering off`，否则聊天看不到逐字输出。

- 图片上传路径 `/uploads/` 已单独配置，权限归运行用户。

- content/ 目录的改动（后台编辑）建议定期 `git add content public/uploads && git commit && git push` 备份。
